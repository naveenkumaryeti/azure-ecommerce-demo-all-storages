# Environment variables (backend, `/etc/ecommerce.env` on VMSS)
| Variable | Required | Purpose |
|---|---|---|
| `STORAGE_ACCOUNT_NAME` | yes | Builds blob/queue/table endpoints `https://<acct>.<svc>.core.windows.net` |
| `BLOB_ENDPOINT` `QUEUE_ENDPOINT` `TABLE_ENDPOINT` | no | Override endpoints (e.g. local emulator) |
| `SESSION_SECRET` | yes (production) | Signs login tokens; **must be identical on all instances**. Generated by `deploy.sh` into `scripts/.state/credentials.env` |
| `SEED_SELLER_PASSWORD` `SEED_ADMIN_PASSWORD` `SEED_CUSTOMER_PASSWORD` | no | Seeds users `SELLER001`, `ADMIN001`, `CUST001` on first start (skipped when blank) |
| `SEED_*_EMAIL` | no | Defaults `seller@/admin@/customer@quickkart.demo` |
| `QUEUE_MAX_DEQUEUE` | no (3) | Attempts before a message goes to `quickkart-order-poison` |
| `QUEUE_VISIBILITY_SECONDS` | no (30) | Invisible time after a receive = retry delay |
| `AZURE_CLIENT_ID` | no | Only for a user-assigned identity |
Local development: `az login`, set the variables, `python app.py` (DefaultAzureCredential uses your CLI login; grant yourself the three Data Contributor roles).
**Production note:** `SESSION_SECRET` and seed passwords travel in cloud-init custom data (readable by root on the VM). Move them to Azure Key Vault (RBAC + managed identity) for real deployments.
